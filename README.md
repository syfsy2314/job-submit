# 秋招投递管理

一个无需安装、无需启动服务的本地秋招投递管理页面。应用代码和示例数据可提交到 Git，真实投递记录只保存在你的电脑上。

## 首次使用

1. 在项目目录中复制示例数据：

   ```powershell
   Copy-Item data/applications.example.json data/applications.json
   ```

   如果已经有自己的 `data/applications.json`，请跳过这一步，避免覆盖真实记录。

2. 使用最新版 Microsoft Edge 或 Google Chrome 双击打开 `index.html`。
3. 点击“打开数据”，选择 `data/applications.json`。
4. 浏览器询问权限时允许读写。之后新增、编辑和删除会自动写入该文件。

也可以在页面中点击“新建数据”创建全新的 JSON 文件。页面顶部会显示当前文件名和保存状态。

## 功能说明

### 进展状态颜色

状态颜色不需要配置，页面会按状态名称自动匹配语义色：

- 待投递 = 灰，已投递 = 蓝灰，笔试 / 测评 = 靛蓝
- 一面 = 琥珀黄，二面 = 橙，三面 = 玫红，HR 面 = 青，终面 = 紫
- Offer = 绿，已拒绝 / 未通过 = 红，已结束 / 放弃 = 深灰

自己新增的状态如果没有命中上面的关键词，会按它在「选项设置」里的顺序，从 16 色色板中挑一个当前没有被占用的颜色（全部用尽后才会循环复用），所以状态之间不会轻易撞色。表格、看板列头、统计卡片使用同一套颜色。

### 下一步安排

每条记录可以填写「下一步日期」「下一步时间」和「下一步备注」：

- 时间可以留空，留空表示只记到日期（全天）
- 备注用来写「二面」「在线笔试」这类简短说明
- 表格中显示为 `2026-09-22 14:00 · 二面`；只有日期时显示 `2026-09-22`，只有备注时显示 `· 二面`
- 填写时间前需要先选择日期

### 表格展示

- 表格按公司分组：公司名作为分组标题并显示记录数，同一家公司的多条投递排在一起；组内先按志愿顺序（未填志愿的排最后），同一志愿再按投递日期从新到旧排列
- 公司分组的先后顺序跟随「排序方式」下拉：最近更新取组内最新的一条，投递日期取组内最前的一条
- 搜索会匹配公司、岗位、备注、下一步备注和志愿
- 「志愿」列用于区分同一家公司的不同岗位（默认选项：第一志愿 / 第二志愿 / 第三志愿 / 服从调剂，可在「选项设置」中维护）
- 「备注」列单行截断显示，鼠标悬停可以查看完整内容
- 看板视图不做公司分组（列本身按状态划分），卡片上会显示志愿标签

## 数据字段

每条投递记录（`applications` 数组中的一项）的字段：

| 字段 | 说明 |
| --- | --- |
| `id` | 记录唯一标识，缺失时自动生成 |
| `company` | 公司名称（必填），表格分组的依据 |
| `role` | 岗位名称（必填） |
| `preference` | 志愿，取自 `options.preferences`，可以为空 |
| `location` | 工作地点，取自 `options.locations` |
| `appliedDate` | 投递日期，格式 `YYYY-MM-DD` |
| `channel` | 投递渠道，取自 `options.channels` |
| `status` | 当前进展，取自 `options.statuses` |
| `nextDate` | 下一步日期，格式 `YYYY-MM-DD` |
| `nextTime` | 下一步时间，格式 `HH:mm`，可以为空 |
| `nextNote` | 下一步备注，最长 60 字，可以为空 |
| `url` | 招聘链接，需以 `http://` 或 `https://` 开头 |
| `notes` | 备注，最长 2000 字 |
| `createdAt` / `updatedAt` | 创建与更新时间，ISO 时间字符串 |

选项分组 `options` 包含 `statuses`（进展阶段）、`channels`（投递渠道）、`locations`（工作地点）、`preferences`（志愿）四组。

旧版本的数据文件可以直接打开：缺少的 `preferences`、`preference`、`nextTime`、`nextNote` 会自动补齐默认值；如果历史数据把时间写在了 `nextDate` 里（例如 `2026-09-22 14:00`），打开时会自动拆分为日期和时间，不会丢失。

## 数据与备份

- `data/applications.json`：你的真实投递记录，已被 `.gitignore` 忽略，不会提交到仓库。
- `data/applications.example.json`：不含真实信息的基础示例，用于初始化和说明数据格式，应提交到仓库。
- 点击“另存备份”可以保存一份带日期的 JSON 副本，不会切换当前数据文件。
- 浏览器可能在刷新、重启或权限过期后要求重新授权，这是浏览器的文件安全机制。
- 如果浏览器无法直接写回文件，页面会切换为导入/下载模式；修改后点击“立即保存”下载新版 JSON。

## Git 与隐私

提交代码时只包含页面、说明和示例数据：

```powershell
git add index.html README.md .gitignore data/applications.example.json
git commit -m "更新秋招投递管理工具"
```

可以用下面的命令确认真实数据已被忽略：

```powershell
git check-ignore -v data/applications.json
```

请勿对真实数据文件使用 `git add -f`。如果它曾经进入过 Git 历史，仅从当前版本取消跟踪并不能清除旧提交中的内容；发布仓库前还需要检查历史记录。

## 兼容性

推荐最新版 Edge 或 Chrome。Firefox 和 Safari 目前不能保证直接写回本地 JSON，但仍可使用导入和下载保存模式。
